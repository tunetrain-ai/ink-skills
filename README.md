## Install

With the [skills CLI](https://github.com/vercel-labs/skills) (works for Claude Code and 75+ other agents):

```sh
npx skills add tunetrain-ai/ink-skills
```

Install everything to Claude Code only:

```sh
npx skills add tunetrain-ai/ink-skills -a claude-code --skill '*'
```

Or install just the skills you need — `npx skills add tunetrain-ai/ink-skills --list` shows all of them.

As a Claude Code plugin, straight from this repo:

```
/plugin marketplace add tunetrain-ai/ink-skills
/plugin install ink-skills@ink-skills
```

As an npm dependency, to vendor the skills alongside a pinned Ink version:

```sh
npm install --save-dev @tunetrain-ai/ink-skills
npx skills add ./node_modules/@tunetrain-ai/ink-skills --skill '*'
```

## Why hierarchical

The [skills CLI](https://github.com/vercel-labs/skills) installs every skill
to a **flat** `<agent>/skills/<name>/` directory, regardless of how deep it
was nested in this repo — so the hierarchy here is authoring structure and a
[skills.sh](https://skills.sh) repo-page grouping, not a runtime tree. What
makes it hierarchical in practice is a single router skill, `ink`, which
loads first and points to the right focused sub-skill for the task at hand
— see [`skills/ink/SKILL.md`](skills/ink/SKILL.md).

## What's in it

Verified against **ink 8.0.0** (requires Node `>=22` and `react` /
`@types/react` `>=19.3.0`) and **@inkjs/ui 2.0.0**. Code samples are
typechecked in CI against the real published package types, not just copied
from documentation; the few fences tagged `no-check` (partial fragments, or
packages that cannot be installed next to Ink 8) are listed by `npm run
typecheck` and are *not* verified. The ecosystem skills go further than
types: each community package's status on Ink 8 comes from installing it,
importing it under Node ESM and rendering it — a declared peer range alone
proves nothing here (several packages that look compatible cannot be loaded).
See [`docs/SOURCES.md`](docs/SOURCES.md) for the generated compatibility table
and how each status was decided.

## Development

```sh
npm install
npm run check     # validate structure + ecosystem data, typecheck every snippet, smoke-import the runtime packages
npm run index     # regenerate skills.sh.json, .claude-plugin/*.json, the table above, and the ecosystem tables
```

`npm run check` is the CI quality gate — see [`scripts/validate.mjs`](scripts/validate.mjs)
for what it enforces (naming, the 3-level depth limit the skills CLI actually
walks, skill-shadowing, where a category folder's own `SKILL.md` would
hide every skill nested beneath it, a `metadata.ink` stamp that must match the
installed Ink, and the ecosystem data in
[`data/ecosystem.json`](data/ecosystem.json)),
[`scripts/typecheck-snippets.mjs`](scripts/typecheck-snippets.mjs) for how
code samples are checked, and
[`scripts/smoke-imports.mjs`](scripts/smoke-imports.mjs) for the Node ESM
import check that types can't give you.

See [`CONTRIBUTING.md`](CONTRIBUTING.md) for the release process and how a
skill gets added.
